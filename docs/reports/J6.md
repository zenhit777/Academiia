## 2. Hypothèses non prouvées

* **« Le routeur est gelé chez DiffusionGemma »** : vérifié **pour les adaptateurs LoRA publiés**
  (aucune clé `router`/`expert`/`vision` dans leurs en-têtes) ; le mécanisme (experts = paramètres
  empilés 3-D, non `nn.Linear`) est établi sur l'index de `checkpoints/gemma4_it`, mais je n'ai pas
  **entraîné** de LoRA pour le confirmer de bout en bout.
* **Le harness de Dream et le protocole A2D coïncident exactement** : le papier dit « *at its
  released decoding settings and per-task budgets* » (App. A.1) sans les énumérer ; j'ai utilisé
  les réglages **du dépôt Dream** (`eval_instruct/eval.sh`), qui concordent avec l'App. A.3
  (T = 0.1, top-p = 0.9, entropie, budgets 256/512/1280). Une divergence résiduelle est possible.
* **La ligne « Base » de la Table 16 (GSM8K 66.5)** : le Dream-7B-Base est un modèle *base* ;
  l'article évalue « *the Dream fork of lm-evaluation-harness […] with the chat template* »
  (App. A.1) sans préciser si le Base reçoit le même template que l'Instruct. Le protocole que
  j'ai appliqué (0-shot + template + prompt système A.1, identique pour les deux modèles) n'est
  **pas** nécessairement celui qui a produit 66.5 (le dépôt Dream utilise 8-shot pour le Base).
  → voir l'écart constaté en §4.
* **Le « MATH-500 » du papier n'a pas été mesuré** : l'App. A.1 dit « *MATH-500 replaces the
  release's full MATH task at its 512-token budget* ». J'ai utilisé les 7 sous-tâches
  `minerva_math` du fork (test MATH, 5 000 problèmes) avec un sous-ensemble par sujet
  (175 problèmes) : ce n'est **pas** le sous-ensemble canonique « MATH-500 » (500 problèmes du
  split PRM800K). La métrique du dépôt est donc **MATH-175 (175/5000)** ; la comparaison aux
  cibles MATH-500 de la Table 16 est **à périmètre différent** et ne constitue pas une
  reproduction — voir §4 (E3) et MAJ-04.
* **Le BF16 vs FP8** : tout le protocole Dream est en **bfloat16** ici (contrairement à la
  campagne J5 en FP8) ; l'effet du FP8 n'est donc pas mesuré.
* **Effet du batching** : `--batch_size 4` (padding à gauche) au lieu de 1 ; un contrôle sur
  16 prompts n'a pas étépossible sur le score, mais le padding est masqué par `attention_mask`.
  Non vérifié à l'identique sur le jeu complet.
