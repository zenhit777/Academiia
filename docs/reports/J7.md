  --diffusion-base checkpoints/dream_7b_base \

  --tau-a-post checkpoints/qwen25_7b_it --tau-a-base checkpoints/qwen25_7b \
  --tau-d-post checkpoints/dream_7b_instruct --tau-d-base checkpoints/dream_7b_base \

  --reference checkpoints/dream_7b_base --mode transfer \
  --tau-a-post checkpoints/qwen25_7b_it --tau-a-base checkpoints/qwen25_7b \

  --reference checkpoints/dream_7b_instruct --mode merge \

  --tau-d-post checkpoints/dream_7b_instruct --tau-d-base checkpoints/dream_7b_base \

## 5. Phase 1 — Plancher de bruit de décodage (mesuré le 2026-10-21)

**Dispositif** : M1 (`checkpoints/dream_7b_instruct`) rejoué sur **GSM8K n=300, lot 4**, protocole
**strictement identique** à la référence J6 ; **seule** la graine torch change
(`0,1234,1234,1234` → `0,1234,4321,1234`). C'est bien la graine **torch** qui pilote
l'échantillonnage : `evaluator.py` lit `torch_random_seed = args.seed[2]` et le tireur du fork est
`torch.multinomial` (`src/diffllm/gen_utils.py`). Durée mesurée : 48 min 43 s (9,66 s/prompt).

**Contrôle bloquant — jeu d'items** : `items_sha256`, `items_order_sha256`, `prompts_sha256`,
`targets_sha256`, `n_items` et `n_samples` sont **identiques** à la référence (la seule
différence de `config` est le champ `torch_seed` : 1234 → 4321). ✔

**Résultat** (`scripts/seed_noise_floor.py`) :

| | Référence (graine torch 1234) | Replay (graine torch 4321) |
|---|---:|---:|
| précision `flexible-extract` | 84,00 % | **84,00 %** |
| réponses **brutes** identiques | — | **300/300 (100,0 %)** |
| réponses **filtrées** identiques | — | **300/300 (100,0 %)** |
| verdicts identiques | — | **300/300 (100,0 %)** |
| écart de précision apparié | — | **+0,00 pt** |
| IC bootstrap apparié 95 % | — | **[+0,00 ; +0,00]** |
| discordantes (McNemar) | — | B seul **0**, A seul **0** |
| écart absolu max par item | — | **0** |

Contrôle d'intégrité : le SHA-256 global des 300 réponses brutes est **identique** dans les deux
runs (`02bd7ecb2aff1df6d039d95b…`) — il ne s'agit pas d'un artefact de comparaison.

**Lecture** : à protocole et lot identiques, le décodage de Dream-7B est **déterministe** : la
graine d'échantillonnage ne change **aucune** sortie.

*Explication* [INFERENCE] : avec `alg=entropy` et `temperature=0,1`, la distribution de tirage
est **très piquée** ; l'échantillon `torch.multinomial` est alors pratiquement déterministe et la
graine n'influence pas le résultat. La variabilité **réellement** documentée par le balayage D3
(`docs/design/EVAL_BUDGET.md` §4.1 : 0 à 5 réponses identiques sur 16 selon la taille de lot)
ne vient donc **pas** du RNG, mais de la **composition du lot** (padding, chemins de calcul, écarts
numériques).

**Conséquence pour G1** : au lot 4 — imposé par le protocole (§3.3) et appliqué à **tous** les
runs — le décodage n'ajoute **aucun** bruit aux comparaisons appariées. L'incertitude restante est
**purement d'échantillonnage** (IC bootstrap apparié), que les critères amendés traitent
explicitement par la borne basse. La sensibilité au lot reste un risque de non-reproductibilité
**entre protocoles différents**, sans effet sur G1.

**Limites** : mesuré sur **une** tâche (GSM8K, 256 tokens) et **un** modèle (M1). La netteté de la
distribution peut différer pour MATH (512 tokens) et IFEval (1 280 tokens) : leur plancher n'est
**pas** mesuré (hors périmètre de la Phase 1, qui demandait GSM8K).

### 6.1 Défaut trouvé par le smoke et corrigé (avant évaluation)

Le **smoke de chargement** des deux checkpoints fusionnés a **échoué** :

```
File ".../transformers/modeling_utils.py", line 557, in load_state_dict
    if metadata.get("format") not in ["pt", "tf", "flax", "mlx"]:
AttributeError: 'NoneType' object has no attribute 'get'
```

Cause : les shards écrits par la bibliothèque **n'avaient pas de bloc `__metadata__`** (safetensors),
alors que `transformers.load_state_dict` l'exige (`format == "pt"`). Autrement dit, un checkpoint
fusionné n'était **pas chargeable** par `from_pretrained` — alors que la vérification
**mécanique** (`post_write_verification` v2, `verify_merge`) passait. Le défaut n'avait jamais été
atteint : la fusion de J6 n'avait été validée que mécaniquement.

Correctif (`4f1b7d6`) : le bloc `__metadata__` est **repris du shard source** (`format: pt` ajouté
s'il manque) et écrit dans l'en-tête ; test de non-regression
(`test_merged_shards_carry_safetensors_metadata`) ; les checkpoints-jouets des tests écrivent
désormais des métadonnées, comme les checkpoints Hub ; garantie documentée (`AGENTS.md`,
`.cursorrules`). Les deux fusions ont été **refaites** avec le code corrigé.
