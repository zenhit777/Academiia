### 3.3 Types de données

| Type | Contenu | Invariant notable |
|---|---|---|
| `ScoringRequest` | préfixe causal `(q, z, Â_i)`, suffixe `Ĉ_i`, candidats `V_i`, token de référence `x̂_i` | candidats non vides, sans doublon |
| `ScoringResult` | prior `r_i(v)` **plein vocabulaire** + scores `s_i(v)` + référence `s_i(x̂_i)` | le prior doit sommer à 1 (±1e-4) ; les **scores non finis sont acceptés** (la cible les dégrade en causal) |

### 3.4 Choix de conception à signaler

1. **`TaskVerifier` et non `Verifier`** : le brief §6.2 désignait `Verifier`.
   Le code retient `TaskVerifier`, plus explicite et sans collision avec
   `academiia.core.text.degenerate`. Le rôle est inchangé ; la note est
   consignée dans `DOPD_SPEC.md` §6.2.
2. **Le bloc `vector` du schéma ADR-002 est omis** : il décrit τ, qui est propre
   à la fusion A2D. d-OPD ne fusionne rien (§6.5). Le manifeste d-OPD porte
   `artifact`, `parent`, `producer`, `config`, `data`, `verification`.
3. **L'écriture sur disque de `lineage.json` n'est pas implémentée** : ADR-002
   assigne l'écriture/lecture générique au module `core`, qui ne l'a pas fait.
   J13 fournit la **construction** du manifeste dans d-OPD et laisse l'écriture
   à une implémentation externe — aucun format concurrent n'est créé.
4. **Convention de maison** : `abc.ABC` + `@abstractmethod` (comme
   `modules/a2d/a2d/sources.py`), pas `typing.Protocol` — le dépôt n'utilise
   pas `Protocol`. Dataclasses figées pour les valeurs, docstrings en français.

## 5. Phase 2 — Smoke Qwen3-0.6B

### 5.1 Principe

Le smoke vit dans `modules/dopd/harness/smoke_qwen3.py`, **hors du paquet
importable** `academiia.dopd`. C'est le seul endroit où `torch` et
`transformers` sont autorisés pour d-OPD (ADR-001 les interdit dans
`modules/dopd/dopd/`). Vérifié : `importlib.util.find_spec("academiia.dopd.harness")`
→ **None**, le harness n'est pas importable comme sous-paquet.

Étapes : tokenizer → modèle en `eval()` sans gradient → forward minimal →
génération triviale → **échantillonnage du prior causal `r_i(v)`** (eq. 11) →
manifeste ADR-002.

**Aucun entraînement** : ni optimizer, ni `backward`, ni `requires_grad=True`.
Le rapport JSON produced consigne `training.performed = false`,
`training.backward = false`, `training.weights_updated = false`,
`training.requires_grad_all_false = true`. Les poids du checkpoint ne sont pas
modifiés.

### 5.2 Commandes exactes

```bash
# CPU (mode par défaut de la mission)
HF_HOME="$PWD/_artefact/hf-cache" python modules/dopd/harness/smoke_qwen3.py \
    --model Qwen/Qwen3-0.6B --device cpu --dtype bfloat16 --local-files-only \
    --output _artefact/dopd_smoke_qwen3_cpu.json

# GPU (optionnel, déclaré)
HF_HOME="$PWD/_artefact/hf-cache" python modules/dopd/harness/smoke_qwen3.py \
    --model Qwen/Qwen3-0.6B --device cuda --dtype bfloat16 --local-files-only \
    --output _artefact/dopd_smoke_qwen3_cuda.json
```

Environnement : venv CPU `~/.venvs/jainius-check` (Python 3.12.3), torch
2.14.1+cu130, transformers 5.10.2. GPU : NVIDIA GeForce RTX 5090, 32 607 MiB
totaux, **30 991 MiB libres** avant le run (aucun modèle chargé).

Le checkpoint `Qwen/Qwen3-0.6B` était **déjà présent** dans le cache
HuggingFace utilisateur. Le script résout l'identifiant HF vers le snapshot
local (lecture seule) et fonctionne donc hors ligne avec `--local-files-only`.
`HF_HOME` est redirigé vers `_artefact/` : **aucune écriture hors du dépôt**
(règle 9 d'`AGENTS.md`).

converti en dLLM par blocs, aucun rollout n'a lieu, aucun bloc n'est
débruité. Il valide **uniquement** le chemin de développement retenu.

## 8. Écarts et observations

1. **`Verifier` renommé `TaskVerifier`**. Le brief §6.2 et la demande J13
   divergeaient sur ce nom. Le code retient `TaskVerifier` ; la note est dans
   `DOPD_SPEC.md` §6.2. Aucune ambiguïté de rôle.
2. **ADR-002 assigne l'écriture de `lineage.json` à `core`**, qui ne l'a pas
   implémenté. J13 construit le manifeste dans d-OPD mais **n'écrit rien sur
   disque** : faire écrire le manifeste par d-OPD créerait deux implémentations
   concurrentes du même schéma. Décision à trancher en J14 (§9, décision 1).
3. **Le bloc `vector` du schéma ADR-002 est omis** dans le manifeste d-OPD : il
   décrit τ, propre à A2D. Le format reste celui d'ADR-002 pour les champs
   communs.
4. **Le checkpoint Qwen3-0.6B était déjà en cache** (1,5 Go, cache HF
   utilisateur, préexistant et hors dépôt). Le smoke ne l'a **pas** téléchargé.
   La résolution vers snapshot local est une lecture seule. L'inventaire des
   écritures hors dépôt n'est pas modifié par J13 (rien de nouveau écrit).
5. **Le run GPU a été exécuté** alors que le mode par défaut de la mission est
   CPU. Il est **déclaré** ici, consomme 1,17 GiB sur un GPU libre de 30,99 Go
   et **ne laisse aucun résidu**. Le mode CPU reste le mode par défaut du
   script.
6. **Le forward GPU (1,359 s) est plus lent que le CPU (0,073 s)** : à cette
   échelle (0,6B, prompt de 6 tokens) le coût de transfert et de
   synchronisation domine. Ce n'est pas une anomalie, mais cela signifie que
   le CPU est un mode de développement **viable** pour les tests de contrat.
7. **`sys.path` non modifié** par le harnais : le script s'appuie sur
   l'installation editable (`pip install -e .`). Une version non installée
   échouerait avec un `ModuleNotFoundError` explicite.
8. **Aucun `torch` dans le paquet** : vérifié statiquement par deux tests
   (global du paquet + test ciblé du fichier d'interfaces) et par le fait que
   `import academiia.dopd` ne charge pas la pile d'entraînement.
